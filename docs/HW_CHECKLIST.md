**Hardware-only suspects for T-4, in order:**
1. **Wrong or stale bitstream.**
   - Check: `ping` build_id and the bit md5 against the H-4 row.
2. **Pins / UART swap.**
   - H-2/H-3 passed with the default pins (FPGA RX = B16 / TX = A16) on 2026-10-24, so the UART pins are proven for data. The swap fallback was not used.
   - Data errors with an intact frame CRC are not a pin problem.
3. **Clock / baud divisor.**
   - Check `DIV_OVERRIDE`: `grep -n "Parameter DIV_OVERRIDE bound to" fpga/reports/top/build.log` must show only `32'b00000000000000000000000000000000` lines (one per UART instance; build.tcl refuses a nonzero override). `summary.json` does **not** carry DIV_OVERRIDE or CLK_HZ; it has only `clk_period_ns` (must be `10.0`) and the `generics` (BUILD_ID, ENABLE_STRIP, ROM_FILE).
   - Check `CLK_HZ`: it is a package constant, not a generic: `git show <B>:rtl/gen/splitsys_pkg.sv | grep "CLK_HZ ="` must print `100000000`, matching `create_clock -period 10.000` on `CLK_100MHZ` (N15) in `fpga/xdc/urbana_splitsys.xdc`.
   - A wrong divisor breaks H-2 first.
4. **BRAM init / ROM `$readmemh` path.**
   - The self-test ROM must come from `sw/crates/vec/out/selftest_rom.mem` at `<B>`.
   - Check the build log for `$readmemh` warnings or "file not found", and `summary.json` for the ROM path.
   - An all-zero ROM gives the zero-output checksum on both jobs.
5. **Timing.**
   - Check: `fpga/reports/top/summary.json` `wns_ns`/`whs_ns` ≥ 0 for this exact build, equal to the manifest row `top` (S4 build: **+0.523 / +0.036 ns**), and the bit md5 equal to the manifest.
   - Errors that are data-dependent, sporadic, or temperature-dependent point here.
   - There is **no** prebuilt fallback bitstream (no 75 MHz or alternate-clock build exists). If a timing-related failure is suspected: first re-run the sim reproduction (T-1/T-2 with `RTL_REV=<B>`, plus `RAND_RESET=1`); only if it passes in sim and the evidence points at timing does the lead decide on a rebuild: `rtl-designer` adds `max_fanout` on the reset replica nets (`u_board/rst_r` → `rst_core_reg_rep__*`, the worst paths of `top` in `fpga/reports/top/paths.rpt`) and on the sequencer `int32_q`, full sim regression (`make -C tb signoff`, `make -C tb/system SIGNOFF=1`), then `bash fpga/tcl/s4_rebuild.sh` (new build_id, new manifest), then `red-team-reviewer` re-review before the board is touched. Never debug on a build with negative slack.
6. **Reset polarity / button level** (`BTN_ACTIVE_LOW`, H-1 record (b)).
   - No heartbeat → BTN1 is read as held, so the design sits in reset.
   - BTN0 does nothing but the SELFTEST opcode passes → BTN0 polarity or debounce.
7. **Power-up state.**
   - Sim with `RAND_RESET=1` covers random initial flops.
   - BRAM powers up as zero, and OBUF poisoning is on in H-5.
   - If only the first job after power-up fails, power-cycle and rerun H-4 before H-5.
8. **USB-UART link drops.**
   - Failures don't repeat with the same seed, and NACK_CRC or timeouts appear in the log → rerun the H-3 memtest.
   - The link is not the datapath.

Only after the cause is identified and the fix is re-verified in simulation (`make -C tb signoff` and `make -C tb/system SIGNOFF=1`) is a new bitstream built and the board touched again.
